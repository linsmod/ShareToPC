# 安卓端设计详细（ShareToPC / Java）

## 1. 概述与现状

- **目标**：出现在系统 Sharesheet 中，接收其他应用分享的文本/文件，通过局域网转发到配套电脑端应用。
- **语言**：Java（`sourceCompatibility / targetCompatibility = JavaVersion.VERSION_11`）。
- **现有工程**：包名 `github.linsmod.sharetopc`，`minSdk = 30`，`targetSdk = 36`，已有 `MainActivity.java` 模板。
- **minSdk=30 的简化结论**：
  - 无需兼容 Android 10 及以下，**不需要** `READ_EXTERNAL_STORAGE`；分享进来的 `content://` URI 直接通过 `ContentResolver` 读取（分享方已临时授权）。
  - 不使用 Scoped Storage 的 `MANAGE_EXTERNAL_STORAGE`，所有临时文件放应用私有目录即可。

## 2. 技术选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言 | Java 11 | 用户指定 |
| 架构 | MVVM：`ViewModel` + `LiveData` | 界面状态驱动 |
| 设备发现 | `NsdManager`（mDNS） | 发现 `_mytransfer._tcp.` 服务 |
| 传输 | `java.net.Socket` + `DataInputStream/DataOutputStream` | 自定义二进制帧协议 |
| 后台清理 | `WorkManager`（`androidx.work:work-runtime`，Java 版） | 延迟清理任务 |
| 设置页 | `androidx.preference:preference` | 清理策略、手动 IP |
| JSON | `com.google.code.gson:gson` | 协议头序列化 |
| 历史存储 | 方案A（默认）：JSON 文件（Gson）<br>方案B（可选）：Room | 控制复杂度，先用 JSON 文件 |
| 依赖注入 | 手动 ServiceLocator（`App` 单例持有） | 不引入 Hilt，降低复杂度 |
| 线程 | `ExecutorService`（定长线程池）+ `Handler(Looper.getMainLooper())` 回主线程 | Socket I/O 全部在后台线程 |

## 3. 整体架构

```
其他App ──ACTION_SEND──> ShareReceiverActivity(透明弹窗)
                              │ 解析+落地到私有目录(inbox)
                              ▼
                        TransferManager(发送队列)
                              │ 选择目标设备
        NsdDiscoveryManager ──┤ (自动发现/手动IP)
                              ▼
                        TransferClient ──TCP──> 电脑端
                              │ ACK/进度回调
                              ▼
                  CleanupScheduler(按清理策略处理文件)
                              │
MainActivity <──LiveData── MainViewModel(发现/连接/传输/历史状态)
```

## 5. 模块详细设计

### 5.1 分享接收（ShareReceiverActivity + ShareParser）

**定位**：透明/对话框样式的 Activity，`excludeFromRecents=true`，处理完即 `finish()`，不进入返回栈。

**流程**：
1. `onCreate` 判断 `Intent.getAction()`：
   - `ACTION_SEND`：取 `EXTRA_TEXT`（String）或 `EXTRA_STREAM`（Uri）。
   - `ACTION_SEND_MULTIPLE`：取 `EXTRA_STREAM`（`ArrayList<Uri>`）。
2. 文本 → 直接构造 `SendEntry(TYPE_TEXT, text)`。
3. 文件 → `ShareParser` 用 `ContentResolver`：
   - `query()` 读 `OpenableColumns.DISPLAY_NAME / SIZE` 得到文件名与大小；
   - `openInputStream(uri)` 复制到 `getFilesDir()/inbox/<yyyyMMdd>/<uuid>_<name>`；
   - 生成 `SendEntry(TYPE_FILE, localPath, name, size, mime)`。
   > 注意：URI 读取授权仅在进程存活期有效，**必须在 Activity 前台时完成复制**，之后再发送。
4. 弹出底部对话框（或 dialog 主题布局）：显示目标设备选择 + 清理策略选择（默认取设置值）+ 发送按钮。
5. 点击发送 → 交给 `TransferManager.enqueue(...)` → 显示进度 → 成功/失败后 `finish()`。

**API 33+ 兼容**：`getParcelableExtra(String, Class)` / `getParcelableArrayListExtra(String, Class)` 新签名，按 `Build.VERSION.SDK_INT` 分支。

### 5.2 设备发现（NsdDiscoveryManager）

- 服务类型常量：`public static final String SERVICE_TYPE = "_mytransfer._tcp.";`
- `startDiscovery()`：`nsdManager.discoverServices(SERVICE_TYPE, NsdManager.PROTOCOL_DNS_SD, discoveryListener)`。
- `onServiceFound` → `resolveService()` → `onServiceResolved` 得到 host/port → 回调 `onDeviceFound(DiscoveredDevice)`，加入去重列表（key = host:port）。
- `onServiceLost` → 从列表移除。
- 提供 `stopDiscovery()`，主界面 `onStop()` 调用，避免耗电。
- **权限**：NSD 发现需要 `ACCESS_FINE_LOCATION`（动态申请，未授权时 UI 提示并提供“手动输入 IP”入口）。
- **备选方案**：NSD 失败（路由器禁 mDNS）时：
  1. 手动输入 IP:端口（设置页 + 主界面对话框）；
  2. （可选增强）监听 UDP 51235 广播包 `SHARETOPC:<port>`，见电脑端文档 §8。

### 5.3 传输（TransferClient / TransferManager）

- `TransferClient`：一次 TCP 会话内可连续发送多条消息（多文件复用同一连接），每条消息发送后**阻塞等待 ACK**（超时 10s）。
- 文件按 64KB 分块读写，每块写完回调 `onProgress(sentBytes, totalBytes)` → `TransferManager` 聚合后 post 到 `LiveData`。
- `TransferManager`：
  - 内部 `BlockingQueue<SendJob>` + 单线程 `ExecutorService` 串行消费，避免并发抢连接；
  - 状态机：`IDLE → CONNECTING → SENDING → DONE/FAILED`；
  - 每个 `SendJob` 关联其内容的 `CleanupPolicy`，全部成功后交给 `CleanupScheduler`。
- 断线重试：连接失败自动重试 1 次（间隔 2s），仍失败标记 `FAILED`，历史记录可见，可手动重发。

### 5.4 清理策略（CleanupScheduler + CleanupWorker）

| 策略 | 实现 |
|---|---|
| 发送后清理 | 收到全部 ACK 后立即 `FileUtils.deleteQuietly()`，删除 inbox 文件（文本无文件则忽略） |
| 一周后清理 | `OneTimeWorkRequest`，`initialDelay = 7 天`，`inputData` 带文件路径 |
| 一月后清理 | 同上，`initialDelay = 30 天` |
| 不清理 | 不调度任何任务 |

- 每个文件一个任务，tag = 文件路径的 hash；策略变更时 `WorkManager.cancelAllWorkByTag()` 后按新策略重新调度。
- 任务持久化由 WorkManager 保证（重启手机不丢失）。
- **兜底**：另注册一个 `PeriodicWorkRequest`（每 24h）扫描 `inbox/`，删除超过 30 天且无对应 Worker 的孤儿文件。
- 记录元数据：`inbox/<date>/` 旁边存 `meta.json`（路径→策略→到期时间），供扫描使用。

### 5.5 主界面（MainActivity + MainViewModel）

- `MainViewModel` 持有 `NsdDiscoveryManager`、`TransferManager`、`HistoryStore`，暴露：
  - `LiveData<List<DiscoveredDevice>> devices`
  - `LiveData<ConnState> connState`（搜索中 / 已发现N台 / 已连接 / 断开）
  - `LiveData<TransferProgress> progress`（当前任务名 + 百分比 + 状态文案）
  - `LiveData<List<SendEntry>> history`
- `MainActivity` 观察以上 LiveData 刷新三个区块（见 §9 布局）。

### 5.6 设置页（SettingsActivity）

- 默认清理策略（列表：发送后/一周/一月/不清理）。
- 手动设备：IP + 端口输入与保存。
- 接收端口约定展示（默认 `51234`）。
- 历史记录清空按钮。

## 6. 传输协议（与电脑端共同约定 v1）

**传输层**：TCP，默认端口 `51234`（两端一致，设置页可改）。

**帧格式**（所有整数 big-endian）：

```
┌──────────────────────┬────────────────────────┬────────────────────┐
│ 4字节 头长度 H       │ H字节 UTF-8 JSON 头     │ 可选 payload       │
└──────────────────────┴────────────────────────┴────────────────────┘
```

- JSON 头上限 64KB（防呆，超过直接断连）。
- 消息类型：

| type | 方向 | JSON 字段 | payload |
|---|---|---|---|
| `HELLO` | 手机→电脑 | `{"type":"HELLO","device":"Pixel 8","version":1}` | 无 |
| `TEXT` | 手机→电脑 | `{"type":"TEXT","text":"...","time":1721952000000}` | 无 |
| `FILE` | 手机→电脑 | `{"type":"FILE","name":"a.jpg","size":123456,"mime":"image/jpeg","time":...}` | 紧跟 size 字节原始数据 |
| `ACK` | 电脑→手机 | `{"type":"ACK","status":"OK"}` 或 `{"type":"ACK","status":"ERROR","msg":"..."}` | 无 |

> HELLO 握手成功后，电脑回复的 ACK 额外携带 `version`、`protoVersion`、`deviceId`、
> `hbInterval`、当前登录用户名 `userName`（Windows `%USERNAME%`）、计算机名 `machineName`
> （`Environment.MachineName`）、真实用户目录 `userFolders`
> （`{"desktop":"C:\Users\...\Desktop","documents":...,"downloads":...,"videos":...,
> "pictures":...,"music":...}`，用 Windows API `SHGetKnownFolderPath` 获取，能正确反映
> OneDrive 重定向等真实位置）以及磁盘列表 `drives`
> （`[{"name":"C:","type":"Fixed","label":"System","format":"NTFS"}, ...]`，
> 来自 `DriveInfo.GetDrives`，type 取 DriveType：Fixed/Removable/Network/CDRom/Ram/Unknown）。
> 手机端按 host 缓存，ETP 文件浏览时直接使用，避免猜测用户名或拼接错误路径。
| `PING`/`PONG` | 双向 | `{"type":"PING"}` | 无 |

**时序**：

```
手机                    电脑
 │ ── HELLO ───────────> │
 │ <────────── ACK ───── │
 │ ── TEXT ────────────> │   （或 FILE + payload）
 │ <────────── ACK ───── │
 │ ── FILE ────────────> │   （多文件：逐条发送，逐条等ACK）
 │ <────────── ACK ───── │
```

- 多文件：同一连接内顺序发送多条 `FILE` 帧，每条等 ACK 再发下一条。
- 全部完成手机端主动关闭连接；电脑端 30s 无数据自动断开。
- 文件名冲突：由**电脑端**负责重命名（`name(1).ext`），手机端不关心。

## 7. AndroidManifest 配置

```xml
<manifest ...>
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
    <uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
    <!-- NSD 服务发现需要（Android 6+ 动态申请） -->
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

    <application ...>
        <activity android:name=".MainActivity" android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <!-- 分享接收入口：一个 filter 覆盖 SEND / SEND_MULTIPLE 全类型 -->
        <activity
            android:name=".share.ShareReceiverActivity"
            android:exported="true"
            android:excludeFromRecents="true"
            android:launchMode="singleTask"
            android:theme="@android:style/Theme.Translucent.NoTitleBar">
            <intent-filter>
                <action android:name="android.intent.action.SEND" />
                <action android:name="android.intent.action.SEND_MULTIPLE" />
                <category android:name="android.intent.category.DEFAULT" />
                <data android:mimeType="*/*" />
            </intent-filter>
        </activity>

        <activity android:name=".ui.SettingsActivity" android:exported="false" />
    </application>
</manifest>
```

> `*/*` 已涵盖 `text/plain`、`image/*`、`video/*`；如需在分享菜单中更靠前可拆成多个 filter 显式列出。

## 10. 异常与边界场景

- 定位权限被拒 → 设备区显示“自动发现不可用”，引导手动输入 IP。
- 分享超大文件（>2GB）→ 流式复制+流式发送，不落两次盘（复制到 inbox 后即从 inbox 流式读出，内存恒定 64KB）。
- 电脑端不在线 → 连接超时 5s，标记失败可重发；inbox 文件按策略保留。
- 发送中途断网 → 当前文件标记 FAILED（记录已发字节数，v1 不做断点续传）。
- 同名/非法文件名字符 → 发送前清洗 `[\\/:*?"<>|]`。
- 横竖屏/进程回收 → 发送在 `ExecutorService` 而非 Activity 中；`ShareReceiverActivity` 被杀后 `TransferManager` 由 `App` 持有继续跑。
- Android 12+ 后台限制：发送由前台用户操作触发，无需前台服务；若后续加“后台排队自动重发”，再评估前台服务（`dataSync` 类型）。
